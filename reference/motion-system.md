# Motion system — Apple-grade animation for decks

The user loved the Apple-style motion found in the research (Emil Kowalski's work, Apple's spring defaults, the Anthropic launch films dissected in huashu-design). This file turns those sources into one system for our fixed 1920×1080 decks. Read it fully before Phase 5 of every deck. Sources: emilkowal.ski (Sonner/Vaul author), the "40 rules of tasteful animation", Apple SwiftUI spring semantics, huashu-design `animation-best-practices.md` / `animation-pitfalls.md` / `apple-gallery-showcase.md`, Tversky & Morrison "Animation: can it facilitate?", NN/g on motion.

## 0. Identity and the one test

You are a motion designer who has studied Apple, Anthropic and Field.io archives, not someone adding `transition: all`. Animation is physics: every easing answers "how heavy is this object, how much friction?" The only metric is the audience's first reaction. "Looks smooth" = good. "That thing really floated off the desk" = great. "That can't be AI-made" = the bar. Taste = knowing when **not** to animate.

Three beliefs: (1) motion is physics, not curves; (2) *time allocation* beats curve shape — Slow-Fast-Boom-Stop is the breath of a good sequence; (3) courtesy to the viewer beats showing off — a 0.4–0.6 s pause before the key result is a technique, not a compromise.

## 1. Should it move at all? (decision framework)

| Event | Frequency in a talk | Decision |
|---|---|---|
| Slide change | 15–30× | Identical, quick, predictable crossfade (0.9–1.2 s), never a wipe/flash. The audience must stop noticing it after slide 2. |
| Element entrance on a slide | once per element | Yes — in reading order, staggered, settled within ~2.2 s. |
| Ambient at rest | continuous | At most one perceptible thing per slide (ring rotation, marquee, slow camera drift). A second one must be barely perceptible (≤ 30 px over 8 s). |
| Signature moment | 2–4 per deck | Yes — this is where the budget goes (diagram draws itself, gallery ripple, number counts up, stamp slam, weight morph). |
| Hover/press | user-initiated | Instant on (≤ 0.3 s), only on real objects (cards, images, nav). Never on text blocks. |
| Click-driven states (focus, toggles, tabs) | — | **Never.** A deck is not a website; sequences play by themselves on a timer. |
| Keyboard-initiated nav | hundreds/day for the presenter | No extra animation beyond the crossfade; side-nav tick pop is fine (0.5 s, once). |

Every animation needs a purpose you can name: reading order · spatial continuity · state change · explanation (mechanism, sequence) · one moment of delight. "It looks cool" is allowed once per deck.

Tversky's two conditions for an animation to teach: **apprehension** (slow and simple enough to be perceived — most animations fail here) and **congruence** (the motion matches the concept: a wave should propagate, a loop should loop, a divergence should grow). Static graphics are usually just as good unless the content *is* change over time; so animate mechanisms, sequences and comparisons, not decoration.

## 2. Easing vocabulary (the brand of the motion)

```css
:root {
  --ease-out:    cubic-bezier(0.16, 1, 0.3, 1);     /* expo-out: default for every entrance (fast start, long brake = weight) */
  --ease-move:   cubic-bezier(0.7, 0, 0.2, 1);      /* ease-in-out: something already on screen relocates/morphs */
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);    /* iOS sheet feel: panels, overlays sliding in */
  --ease-reveal: cubic-bezier(0.77, 0, 0.175, 1);   /* clip-path / mask reveals */
  --ease-linear: linear;                            /* marquee, progress bar, ring rotation only */
}
```
Springs: use `reference/springs.css` (generated by `scripts/spring.py` from Apple's `Spring(duration:bounce:)` mapping — CSS `linear()` strings): `--ease-smooth` (no overshoot: text, cards), `--ease-snappy` (bounce 0.15: pills, discs, cards landing), `--ease-bouncy` (0.3: one hero object per deck), `--ease-gentle` (slow, heavy: full-bleed images, big shapes), `--ease-slam` (0.35: stamp/seal landing). Pair each with its `--dur-*` (the settle time). `linear()` is supported in Chrome 113+/Safari 17.2+/Firefox 112+; keep a `cubic-bezier` fallback declared first.

Rules: never `ease-in` on UI; never `linear` on objects; never bounce on text; springs on **objects** (discs, stamps, cards, images), expo-out on **type**. One deck = one easing family; do not mix expo-out and springs on the same element.

## 3. Durations for a 1920×1080 stage

UI rules (≤ 300 ms) are for buttons; a stage is bigger and slower, and the user asked for "чуть медленнее". Defaults:

| Thing | Duration | Notes |
|---|---|---|
| Text/card entrance (fade + rise 24–40 px) | 0.9–1.1 s expo-out | `--dur: 1.1s` in QED v1 after slowing |
| Stagger step | 0.14–0.16 s (cascade), 0.06–0.09 s (words) | groups of 3–7; tables up to 12 rows |
| Slide crossfade | 1.0–1.2 s ease-in-out | opacity only |
| Chrome rules drawing (scaleX) | 1.3–1.5 s | starts 0.2 s in |
| Signature moment (draw-in, count-up, ripple) | 1.4–2.2 s | may start after a 0.3–0.5 s beat |
| Stamp slam | 0.7 s spring, delay 1.3–1.6 s | after the text has landed |
| Ambient loops | ring 45–60 s, marquee 50–70 s, disc drift 9–12 s alternate, image camera 12 s once | slower than a blink |
| Hover | 0.25–0.35 s out, instant-ish in | |
| Settle deadline | everything still by 2.2 s (2.6 s on a 12-row table) | then only the one ambient moves |

Slow-Fast-Boom-Stop inside one slide: kicker and hairline (slow, 0–0.4 s) → heading (fast, 0.3–1.0 s) → cascade of supporting items (0.5–1.6 s) → signature boom (stamp/diagram/number, 1.3–2.2 s) → stop: nothing else moves. Between slides the same shape repeats, so the audience learns the rhythm.

## 4. Choreography rules

1. Reading order: top-left → bottom-right; background/shape first, foreground text last **except** the hero heading, which leads.
2. Opacity always pairs with a small transform (rise 24–40 px, or scale .96→1, or blur 8→0). Never opacity alone, never `scale(0)`.
3. Stagger only related items; lead with the most important; 3–7 per group.
4. One choreography per slide. If a slide needs two systems (e.g. cards + a diagram), the diagram is the signature and starts after the cards land.
5. Quiet slides: at least 3 slides per deck have only the cascade and no ambient device — silence makes the loud ones work.
6. Slide-to-slide continuity: keep the chrome (head/foot rules, side nav) static so the eye has an anchor while content crossfades.
7. Never animate layout properties (width/height/top/left/margin). Transform, opacity, filter, clip-path only. `will-change: transform` only on the 1–3 heavy elements.
8. `prefers-reduced-motion`: keep opacity fades, drop movement (viewport-base.css already shortens everything).
9. Measure after `document.fonts.ready` (path lengths, split words); give every parent of an absolute child `position: relative`.
10. Transitions over keyframes for anything that can be interrupted (slide changes mid-animation must not snap).

## 5. Apple-grade recipes (copy-paste)

### 5.1 Blur-in (Keynote "Focus") — the default text entrance for premium decks
```css
.blur-in { opacity: 0; filter: blur(10px); transform: translateY(18px) scale(.985); transition: opacity 1s var(--ease-out), filter 1s var(--ease-out), transform 1s var(--ease-out); }
.slide.visible .blur-in { opacity: 1; filter: blur(0); transform: none; }
```
Keep blur ≤ 12 px (Safari cost). Use for headings and big numbers; ordinary body text uses plain fade + rise.

### 5.2 Word-by-word build (Keynote titles) — no library needed
```html
<h1 class="words">Forces are exchanged photons</h1>
```
```js
document.querySelectorAll('.words').forEach(h => { h.innerHTML = h.textContent.split(' ').map(w => `<span class="w"><span>${w}</span></span>`).join(' '); });
```
```css
.words .w { display: inline-block; overflow: hidden; vertical-align: bottom; }
.words .w span { display: inline-block; transform: translateY(110%); opacity: 0; filter: blur(6px); transition: transform .9s var(--ease-out), opacity .6s, filter .9s; }
.slide.visible .words .w span { transform: none; opacity: 1; filter: blur(0); }
.slide.visible .words .w:nth-child(n) span { transition-delay: calc(.12s + var(--i, 0) * .08s); } /* set --i via JS or nth-child list */
```
For lines instead of words (smoother for 3-line hero titles) split by `<br>` and mask each line. GSAP SplitText (free) does words/lines/chars with masks in one call when a deck already loads GSAP.

### 5.3 Mask reveal for images and cards
```css
.mask-in { clip-path: inset(0 100% 0 0); transition: clip-path 1.4s var(--ease-reveal) .2s; }
.slide.visible .mask-in { clip-path: inset(0 0 0 0); }
```
Bottom-up for portraits (`inset(100% 0 0 0)`), left-to-right for wide scenes. Pair with the slow camera (5.7).

### 5.4 Scale-in for cards/modals (never from 0)
```css
.pop { opacity: 0; transform: scale(.96) translateY(12px); transition: opacity .8s var(--ease-out), transform var(--dur-snappy) var(--ease-snappy); }
.slide.visible .pop { opacity: 1; transform: none; }
```

### 5.5 Focus pull (one thing sharp, the rest recedes) — for step-throughs and galleries
```css
.focus-group.is-focused > :not(.focus) { filter: blur(4px) brightness(.72) saturate(.7); opacity: .55; transition: filter .7s var(--ease-out), opacity .7s; }
.focus-group .focus { transform: scale(1.04); transition: transform .7s var(--ease-out); }
```
Blur is what makes the background *recede*; opacity alone leaves it sharp. Optionally a 150 ms white flash (`animate()` background rgba(255,255,255,.3)→0) on the focused element to lead the eye.

### 5.6 Count-up numbers
```js
function countUp(el, to, ms = 1400, dec = 0) { const t0 = performance.now(); const from = 0; (function f(now){ const p = Math.min(1, (now - t0) / ms), e = 1 - Math.pow(2, -10 * p); el.textContent = (from + (to - from) * e).toFixed(dec); if (p < 1) requestAnimationFrame(f); })(t0); }
```
Trigger when the slide becomes visible; `font-variant-numeric: tabular-nums` so digits don't jitter. One count-up per slide, never for numbers that must be read precisely at first glance (show the exact value after the count).

### 5.7 Slow camera and drift (ambient)
```css
.scene img { transform: scale(1.02); transition: transform 12s ease-out; }  .slide.visible .scene img { transform: scale(1.06); }
@keyframes drift { to { translate: 0 -30px; } }  .slide.visible .disc { animation: drift 11s ease-in-out 1.6s infinite alternate; }
```
For tilted galleries use a sinusoidal pan with different X/Y frequencies (0.12 vs 0.09 rad/s) plus a slow linear drift so the loop is never predictable.

### 5.8 Draw-in (SVG paths, rules, underlines)
`stroke-dasharray = stroke-dashoffset = getTotalLength()` → transition dashoffset to 0 over 1.6–2 s expo-out; vertices/labels pop after. Our `data-feyn` builder in `templates/example-qed-deck.html` does this for diagrams; rough-notation (vendored) draws hand-made underlines/circles/boxes around words: `RoughNotation.annotate(el, {type:'underline', color:'#E39B1E', strokeWidth:3, animationDuration:900}).show()`; vivus draws whole illustrations.

### 5.9 Variable-font weight morph (wordmarks, one per deck)
`font-variation-settings: "wght" 200 → 800` over 0.9 s expo-out with tracking −0.045 → −0.048 em. Needs a variable font (Fraunces, Onest, Manrope, Inter, Recursive).

### 5.10 3D gallery wall (Apple product-page "works wall") — when you have ≥ 12 same-format tiles
`perspective: 2400px`, canvas `rotateX(10–14deg) rotateY(±8–12deg) rotateZ(±2–3deg)`, tiles with `padding: 6px; border: 1px hairline; box-shadow: 0 20px 60px -20px rgba(0,0,0,.12), 0 6px 18px -6px rgba(0,0,0,.06)`, two shadow tiers instead of per-tile translateZ (same look, 10× cheaper). Entrance: ripple by distance from centre (delay = dist/maxDist × 0.8 s, each 0.7 s expo-out) while the canvas scales 1.25 → 0.94. Then focus pulls (5.5) on 2–4 tiles, 1.7 s each with 0.6 s breathing gaps. Full spec: `library/huashu-design/apple-gallery-showcase.md`.

### 5.11 Stamp slam, band slide-in, disc pop (house devices when the style calls for them)
Stamp: `scale(2.4) blur(6px)` → `scale(1)` with `--ease-slam`, delay after text; ring rotates 50 s linear. Band: `translateX(-120px)` → 0 over 1.3 s expo-out; marquee 64 s linear, text twice. Disc: `scale(.2)` → 1 with `--ease-snappy` (1.5 s), then drift.

### 5.12 Hover (real objects only)
Cards: `translateY(-5px)` + shadow grow, 0.3 s; images: `scale(1.03)` 0.8 s; pressable: `scale(.97)` on `:active` 160 ms; gate hovers with `@media (hover: hover) and (pointer: fine)`.

## 6. Libraries — when CSS is not enough

| Need | Use | Vendored at |
|---|---|---|
| Line/word/char masks with one call, timelines with overlaps, seek | GSAP 3.12 + SplitText (both free) | `library/vendor/gsap.min.js` (+ SplitText from cdnjs when online) |
| True springs with velocity, stagger helpers | Motion (`animate(el, {transform}, {type:'spring', duration:.5, bounce:.2})`) | `library/vendor/motion.js` |
| Hand-drawn underline/circle/box/bracket | rough-notation (3.8 KB) | `library/vendor/rough-notation.iife.js` |
| Sketchy shapes/diagrams | rough.js | `library/vendor/rough.js` |
| Draw an SVG illustration | vivus | `library/vendor/vivus.min.js` |
| Split text without GSAP | Splitting.js | `library/vendor/splitting.min.js` + `.css` |
| Formulas | KaTeX (cdnjs) | — |

Decks open from `file://`: copy the needed file into `<deck>/lib/` and load it with a relative `<script>`; CDN only as a second option. 80 % of decks need none of these — CSS transitions + the recipes above are enough and are the most robust.

## 7. Signature-moment menu (pick 2–4 per deck, each on a different slide)

Keynote word build (5.2) · Letter blur-in (5.13) · Diagram draws itself (5.8) · Level-staged mechanism: org chart, loop with an orbiting dot (5.16) · Number counts up (5.6) · Image mask reveal + slow camera (5.3 + 5.7) · Wall ripple as a background (5.15) · Hero stamp entrance (5.14) · Wordmark weight morph (5.9) · Hairline that draws across the slide · Dimension line that measures the title · Photo un-desaturating on hover. Name them in `brief.md` before building; no slide gets two.

## 8. Motion QA (before delivery)

- Slow-motion test: temporarily set `--dur` ×3 and watch one loud slide — any element starting/stopping abruptly, wrong transform-origin, two things competing?
- First frame of every slide (screenshot at `--virtual-time-budget=6000`) is a complete, composed frame; the settled state is the designed state.
- After 2.2 s nothing moves except the one ambient device. No slide has particles + glow + parallax + tilt.
- No wipes/flashes between slides; crossfade only (the user called wipes "эпилептическое моргание").
- Reduced-motion still looks designed.
- Every animated element uses transform/opacity/filter/clip-path only; blur ≤ 12 px; `will-change` on ≤ 3 elements per slide.
- The "cover the text" test: with text hidden, does the motion alone tell which deck this is? If not, the signature moments are generic.
- Cascades inside tables: a mid-animation screenshot (`--virtual-time-budget=1400`) must show the rows arriving one by one — the implicit `<tbody>` swallows `.stagger > *` delays (see pitfalls).

## 9. Anti-patterns (instant AI-slop signals)

`transition: all` · everything fades in with no direction · linear easing on objects · bounce on text · `scale(0)` entrances · every slide has particles · logo/wordmark that merely fades in · uniform rhythm (every element same delay, every slide same timing) · fade-to-black endings (end on a held, sharp frame) · focus change by opacity only · animations that block reading (a 10-item list dumped in one stagger; use two beats or reveal on key) · pseudo-chrome (fake progress bars, timecodes) drawn inside the slide.

### 5.13 Letter-by-letter blur-in (budget: 1–2 slides per deck — title hero and closing)
```css
.letters .l { display: inline-block; opacity: 0; filter: blur(12px); transform: translateY(.12em); transition: opacity .9s var(--ease), filter .9s var(--ease), transform .9s var(--ease); transition-delay: calc(var(--l0, .3s) + var(--i, 0) * .05s); }
.slide.visible .letters .l { opacity: 1; filter: blur(0); transform: none; }
```
`buildLetters()` (in `templates/example-qed-v3-deck.html`) wraps every non-space character in `.l` with `--i`, recursing into child spans and keeping `<br>`. 24 letters × 50 ms + 0.9 s ≈ 2.1 s — the settle deadline; do not use it on long lines.

### 5.14 Hero stamp entrance (two stamps per deck get it; the rest use the ordinary slam)
```css
.stamp.hero.reveal { transform: scale(1.8) rotate(9deg); filter: blur(14px); transition: opacity .6s ease, transform var(--dur-slam) var(--ease-slam), filter .9s ease; }
.slide.visible .stamp.hero.reveal { opacity: .92; transform: scale(1) rotate(0); filter: blur(0); transition-delay: 1.7s; }
```
The blur reads as the stamp "arriving from above the paper"; the spring gives it weight. Reserve for the title and the closing.

### 5.15 The 3D wall — a background, never a panel
A tilted canvas (`perspective 2400px`, `rotateX(12deg) rotateY(-9deg) rotateZ(-2deg)`, `scale(.82)`) of 12 tiles (diagrams, forms, cards) that ripple in by distance from the centre, then pan slowly (46–60 s alternate). Top and bottom scrims (240–260 px gradients above the wall) keep chrome and headings legible; tiles at opacity .16–.24; `pointer-events: none`. Use it once or twice per deck as the atmosphere behind a statement (mid-deck) or the closing. **No focus cards, no click-to-focus, no timed pop-ups on top of it** — the user rejected both the interactive and the timed variants ("це презентація, а не сайт"). Code: `templates/example-qed-v3-deck.html` (`.wall`, `.tile`, closing slide) and the wall of blueprint forms in `presentations/burokratiya-v2/burokratiya-v2.html` (`buildForms()`).

### 5.16 Level-staged mechanism (org chart, vicious circle) — the blueprint deck's signature
Every stroke element of `svg.mech` carries `--lv` (0 = the root); strokes draw with `stroke-dashoffset` over .85 s expo-out delayed `calc(.7s + var(--lv) * .15s)`, fills fade .6 s later, labels at `1.2s + lv × .15s`, arrowheads pop with the snappy spring. Top-down for a hierarchy (congruent: the chart *is* the subordination), clockwise for a loop; the loop's ambient is one dot orbiting the centre (`ring-turn 16s linear`, gated by `.slide.visible`, starting after the last arc at ≈ 2.6 s). Eight levels settle by ≈ 2.7 s — acceptable for the slide's one signature; nothing else on that slide may be loud. Code: `templates/example-blueprint-deck.html` (`svg.org`, `svg.loop`, `measureDraw()`).
